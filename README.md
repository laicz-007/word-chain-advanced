# 单词接龙 · Word Chain

一个英语单词接龙网页游戏，支持 **人机对战**、**本地同屏** 与 **联机房间**。采用**数据与网页分离**架构：服务端持有统一词库并运行规则/AI，网页只调接口。纯 Node 内置模块，**运行时零第三方依赖**——拿到项目直接 `node server.js` 就能玩，无需任何构建（轻量词库随项目提供）；只有「生成全量词库」这个**可选**步骤需要 Python 3，详见下文「运行」。

## ✨ 核心特色

### 🔤 接龙规则：接**末尾 2/3 个字母**

与"首尾同字/同音"不同，这里的新词开头必须**对上上一个词的末尾 2 个字母，或 3 个字母**：

- `apple` 的末尾是 `le`，下一个词可以 `lemon`（对 2 字母 `le`）……
- 任一方长度 <3 时只要求 2 字母匹配；结尾还要含元音、排除 `ry/ht/ck` 等难接墙

规则简单但**变化极深**：词库 33 万词按"结尾 → 能接的开头"预建索引，每一步都能实时给出可接候选。

### 🤖 AI 不靠蛮力，靠"权重操控 + 自主学习"

这是本项目最花心思的部分——AI 不是随机出词，而是一个**可解释的加权评分引擎**：

- **四维加权评分**（`AI_WEIGHTS`）：防疲劳 0.30 + 难度贴合 0.23 + 词频 0.23 + 可接指数 0.24，再乘随机扰动 S5∈[0.93,1.07]。每个 AI 出词都会在界面上**亮出它的"选词依据"**（目标难度、实际难度、词频、可接指数），你可以直接看到 AI 在想什么。
- **难度贴合 = 读懂你**：登录账户 → 用**学习画像**（难度舒适区/已知词/薄弱结尾）定目标难度；游客 → 按你最近 5 个词的难度实时估。AI 永远在"够得着又有点挑战"的区间出题。
- **自主学习/教学导向**：画像里统计"你未见过且带知识点的词"，这类词额外加权 ×1.18 优先喂给你——**玩着玩着就把生词教给你了**。
- **防疲劳软惩罚**：按"全时段已用次数"给 0~1 权重，跨会话持久化，AI 会刻意避开你用滥的词，保持新鲜感。
- **结尾多样化激励**：AI 记住最近喂给你的 10 个结尾，重复的降权，逼它换花样，不让你总接同一个套路。

> 详细算法见下方「AI 选词算法」章节。

### 其它特色
- **账号系统**：注册/登录（scrypt 加盐散列 + HMAC token），登录后画像/记录/防疲劳按账户存服务端，跨设备同步
- **联机房间**：多设备在线对战，创建/加入房间、房主开局/终止、**60 秒未出词自动认输**、轮到时高亮+倒计时
- **学习画像面板**：难度水平、已知词数、薄弱结尾一眼可见
- **4 套主题**：原版 / Claude 暖白 / 柔和渐变 / 夜读游戏

### 玩法机制（按模式区分）

**先看范围**：项目有三种对局模式（人机对战 / 本地同屏 / 联机房间）与两种交付形态（网站版 / 离线便携版）。
"竞技规则"只在**联机房间**启用 —— 单机玩法保持轻松。

| 功能 | 人机对战 | 本地同屏 | 联机房间 | 离线便携版 |
|---|---|---|---|---|
| 词库清理（生僻回声词、缩写等已删） | ✅ | ✅ | ✅ | ✅ |
| 禁止回声 / 专名限额 / AI 验词 / 道具 | — | — | **✅** | — |
| 积分（挣分） | ✅ | — | ✅ | — |

- **禁止回声**（仅联机房间）：新词**不得恰好等于**上词的末尾 2/3 字母。起因是房间对战里 A 出 `abarticular`，
  B 直接回一个 `lar`（生僻却能接，**一看就是在偷懒**）。**高频词例外**：`to` / `be` / `as` 这类常见词允许回声。
- **专名限额**（仅联机房间）：人名/地名/姓氏**不从词库删**（删了会制造死路），改为**每人每局最多用 3 个**，
  同时 AI 会重度降权避开它们；记分板显示「专名 N/3」。
- **AI 裁判（验词）**（仅联机房间）：出了可疑的词（生僻 / 秒回 / 难度突跳 / 超出你的水平）会**暂停本轮**，
  弹**四选一**（3 个释义 + 「以上都不对」）让你证明自己认识它。限 **15 秒**作答；
  **答错或超时扣 1 分、答对不扣，接龙都由下一位继续**（词在弹窗之前就被接受了，所以超时只扣分、不判负）。
  判定结合**本局状态**与**你账户的历次对局画像**。
- **积分与道具**：每出 1 词 +1、赢一轮 +10（长接龙额外加成）。积分在**人机对战与联机房间**都能挣；
  **道具**（跳过卡 / 修改卡 / 反转卡，每局每人限 3 次）只能在**联机房间**购买与使用；
  库存与积分由服务端权威扣减。
  > 修改卡换出来的词**计入接龙长度**，但**不计入"你出过的词"**（不进记录/生词表）——它是卡片给的，不是你出的。
- **1v1 单挑**（仅联机房间）：房间里可向他人发起单挑，对方接受即开战（**拒绝不打、无任何惩罚**）；其他人等待或旁观。
- **密码修改**：账号栏可直接改密码；改后**其他设备上的登录状态立即失效**（token 版本号机制）。

> 两种交付形态：
> - **网站版（本仓库 server.js）**：部署到服务器/VPS，支持**账号（注册+密码登录）+ 游客**；登录后**学习画像细化到账户**、对局记录/防疲劳/生词/最高纪录都存服务端，跨设备可读。游客只做**最低限度 localStorage**（同便携版），不登录、不做数据归并。
> - **便携版（单文件 `word-chain-standalone.html`）**：双击即玩，**纯游客**，数据存浏览器 localStorage，并保留**以浏览器为单位的学习画像**（离线版不带账号，但画像功能与最初一致）。

> 统一词库由脚本从 3 个开源项目自动整合（`python tools/build_unified_db.py`）：
> - **ECDICT**(skywind3000/ECDICT)：兜底词覆盖 + 音标/中文释义/词频/考试标签/柯林斯星级（数十万词条）
> - **Tofu-Xx/dictionary**：中文释义 + 英音/美音音标
> - **KyleBing/english-vocabulary**：逐词精讲（例句/短语/近义/同根/真题），用于"知识点"

## 运行

只需要 **Node.js（≥14）**。

### 方式一：直接跑（推荐，零构建）

词库有两份，**轻量词库 `data/db.lite.json`（约 3.7 万词）已随项目提供**，所以拿到项目后**不需要任何构建步骤**：

```bash
node server.js        # 启动服务端
# 浏览器打开 http://localhost:8080
```

Windows 可直接双击 `启动游戏.bat`。换端口：`PORT=9000 node server.js`。

启动时控制台会显示当前用的是哪份词库：

```
词库词条: 36809（含知识点: 13884）
词库来源: 轻量词库 data/db.lite.json（随项目自带，可直接玩）
```

### 方式二：换成全量词库（可选，需要 Python 3）

全量词库 `data/db.json` 约 **28 万词**、文件 **84MB**，**没有随项目分发**（太大），需要自己生成。
这一步额外需要 **Python 3**：

```bash
npm run build         # 依次执行下面三步
#   1. python tools/build_data.py         -> public/vocab.json（基础词库，不联网）
#   2. python tools/build_unified_db.py   -> data/db.json（全量词库，首次需联网下载约 80MB）
#   3. node   tools/compute_chain_idx.js  -> 预计算可接指数 + 过滤缩写/专名
node server.js        # 存在 data/db.json 时会自动优先使用它
```

> 第 1 步的产物 `public/vocab.json` 已在仓库中，所以通常会自动跳过。

### 词库是怎么选的？

**自动判断，不需要任何配置**：

| 情况 | 使用的词库 | 词量 |
|---|---|---|
| `data/db.json` 存在（跑过 `npm run build`） | 全量 `data/db.json` | 约 30 万 |
| 否则 `data/db.lite.json` 存在（默认情况） | 轻量 `data/db.lite.json` | 约 3.7 万 |
| 两份都没有 | 启动时报错，并提示你运行 `npm run build` | — |

两份词库都够正常游玩，全量库词更丰富、生僻词更多。

> ⚠️ **已知差距：轻量词库 `db.lite.json` 停留在 2026-09-05，没有跟上后来的词库清理。**
> 它里面还留着 `sis`（＝sister）、`te`、`ide`、`ole`、`mic`、`os` 这类依附型/缩写词，
> 而且 `action`、`abroad`、`ace` 这些超常用词被旧版规则**误判成专名** ——
> 在联机房间里会白白占用每人每局 3 个的专名额度。
> 它也没有对应的生成脚本（是一次性产物），因此暂时无法一键重建。
> **影响范围**：只有"没跑过 `npm run build` 的全新克隆"和"离线便携版（`word-chain-standalone.html`）"。
> 本机只要存在 `data/db.json`，游戏用的就是已清理干净的全量库。

## 游戏规则

- 若干玩家**按序**出词。
- 玩家1 给出开局词 S1（来自词库 / 或任意英文词，见下）。
- 后续玩家给出的词必须满足规则 1-4：

1. **接龙匹配**：新词开头 2 字母 = 上词末尾 2 字母，**或** 开头 3 字母 = 上词末尾 3 字母。
   - 若上词或新词任一方长度 <3，则**只考虑 2 字母匹配**。
2. **末尾元音**：结尾最多 3 个字母（不足 3 取全部）必须含 1 个元音（`a e i o u y`，`y` 算元音）。
3. **禁止结尾（数据驱动）**：不能以 `ry` / `ht` / `ck` 结尾。这三组是"常见却难接"的双辅音/类双辅音结尾（`ry`：sorry/very/story/history；`ht`：light/right/thought/night；`ck`：back/rock/check），由"结尾常见度 × 难接度"分析筛出。
4. **最短长度**：单词至少 2 个长度（例如 `am`、`lap` 都合法）。
5. **禁止回声**：新词不得**恰好等于**上词的末尾 2 或 3 字母（`xxxlar → lar` 这类"偷懒"被拦）；
   高频词（`to`/`be`/`as` 等）例外，允许回声。

**计分**：
- 一方认输时（玩家手动 / AI 判定无词可接），**上一个成功出词的人 +1 分**，认输方成为下一轮开局者。
- 若认输发生在起始词之后、第一个接龙词之前，则起始词提供者得分。

**去重**：同一轮内单词不得重复；认输进入下一轮后，重复判定清空。

## 账号与游客（网站版）

- **游客（不登录）**：照常玩，数据只存当前浏览器 localStorage（`wc_games`/`wc_seen`/`wc_usage`/`wc_best`），**不做学习画像**——AI 难度按"最近 5 词"估算。
- **注册 / 登录**：用户名（2-20 位字母/数字/`_`/`-`）+ 密码（4-64 位）。密码以 **scrypt 加盐散列**存储（`data/users.json`，不存明文），登录态为**HMAC 签名 token**（30 天，密钥存 `data/.secret`）。
- **登录后**：账户数据存在 `data/sync/<用户名>.json`（`usage` 防疲劳 / `seen` 生词 / `best` 最高纪录 / `games` 对局记录）。人机对战时服务端用该账户**计算学习画像**（难度舒适区 / 结尾接词习惯 / 薄弱结尾 / 知识面），AI 按画像贴合难度并**优先喂"含知识点且你未见过"的新词**。
- **明确不做**：游客本地数据登录后**不归并**进账户；两者各自独立。游客数据就是游客数据，账户数据就是账户数据。
- 相关接口：`/api/register`、`/api/login`、`/api/logout`、`/api/me`、`/api/record`、`/api/start`（带 token 绑定账户）、`/api/reset-usage`（按账户重置防疲劳）。

## 模式

### 人机对战（PvE）
- 玩家先手。AI 只从词库中选词，并计算**目标难度**：**登录账户→按账户学习画像**（持久）；**游客→最近 5 次成功出词的平均难度**，从合法候选词中选出**难度最接近该目标**的词。
- 若难度相近（目标难度的 ±10% 内），则优先选**词频更高**的词。
- 界面会展示 AI 的选词依据（目标难度 ≈X.X、实际难度、词频）。
- **探索 · 发现 选项**：勾选后，**初始词由 AI 随机选一个"有趣"的词**（有知识点、非死路、难度适中、可接性好），玩家再从这个词往下接龙。

### 多人对战 = 两种：本地同屏 / 联机房间

#### 本地同屏（单设备，离线/网站版都有）
- 选择 2-6 名全人类玩家，在同一台设备上轮流接龙，自动计分。
- 玩家给出**不在词库**的词：**先弹一次确认提示**（提示"不在词库、不计入难度统计"），确认后才接受。
- **统计我的出词**（可选）：勾选并指定"我是哪位玩家"后，只有你这位玩家的接龙词计入记录/防疲劳/学习画像（避免把同屏其他人的词混进你的画像）；接龙面板与记录里会用 **「我」** 标出你的词。

#### 联机房间（多设备服务器版，需登录）
- **必须注册/登录** 才能创建或加入房间（游客不可用）。
- 进入"联机房间"→ **创建房间**（随机 **6 位房间号**，创建人即**房主**）或 **加入房间**（输入房间号自动加入）。
- 同一账号同时只能在一个房间；房间上限 6 人。
- **房间按钮按身份区分**：**房主 = 开始对战 / 解散房间**（解散即整房解散、所有人退出）；**其他人 = 离开房间**。开始对战仅房主可见。
- **开局**：房主在房间 ≥2 人时可"开始对战"；**终止**：对局中房主可"终止对局"（回到房间等待）或"解散房间"（解散整房，其他人会看到提示）。
- **各端同步**：每端约 0.8s 轮询同步同一盘棋。**无求助提示**；轮到你时输入框可用，别人轮到时会显示 **「xxx 接龙中…」**，你不能抢出词（服务端也会拒绝越回合）。
- 相关接口：`/api/room/create|join|leave|start|action|terminate|dissolve`（POST）+ `/api/room/state`、`/api/room/mine`（GET）。

### 接龙面板
面板始终展示最近两个词，方便看清自己刚出的词与释义：
- **上上个人出的词**（上一轮自己/对手的词）
- **上个人出的词**（待接的词，高亮）
- 下方为**输入框**。每个词均带中文释义与难度徽章。

## 促进学习的巧思（已审核通过）

- **出词即记忆**：每个词都展示英文 + 中文释义 + 难度徽章。
- **AI 选词依据可见**：AI 出词后标注其目标难度与选词难度，让玩家感知自己所在水平。

> 其余超出文档的创意（连对加分、生词本、难度走势图等）已在开发前征求确认，**均未实现**。

## 重新构建词库

词库的生成是**三步链路**，缺一不可。不要混淆：真正生成全量词库的是 **`build_unified_db.py`**（unified = 统一整合），其它两个是它的前/后处理。

| 步骤 | 脚本 | 产出 | 是否联网 |
|---|---|---|---|
| 1 | `python tools/build_data.py` | `public/vocab.json`（基础词库，用 `data/word.csv`） | 否 |
| 2 | `python tools/build_unified_db.py` | `data/db.json`（全量词库，整合 ECDICT/Tofu/Kyle） | 首次需联网，有缓存则离线 |
| 3 | `node tools/compute_chain_idx.js` | 给 db.json 算可接指数 + 过滤缩写/专名 | 否 |

### 一键重建（推荐）

`build-db.sh` 是上面三步的**一键入口**（内部依次调用 1/2/3），在项目根目录执行：

```bash
bash build-db.sh
```

等价于 `npm run build`（package.json 里已配成这三步）。跑完重启服务生效：

```bash
sudo systemctl restart word-chain
```

### 单独跑某一步（维护时用）

```bash
python tools/build_data.py                 # 只重建基础词库 vocab.json
python tools/build_unified_db.py           # 只重新整合全量词库 db.json
node tools/compute_chain_idx.js            # 只重算可接指数/过滤缩写
```

> 说明：`build_unified_db.py` 输出的是**全量** db.json（约 33 万词）；`compute_chain_idx.js` 会剔除缩写/专名（`kind<=0.1` 且不在常用词白名单）并写入可接指数，最终约 **28 万词**。
>
> `data/db.lite.json` 是**另一份独立提供的轻量词库**（约 3.7 万词，随项目分发），离线单文件版与服务端兜底都用它。注意它是早期生成的快照，**不是**全量库按词切出来的子集：两者的词条集合与 `chain_idx` 数值并不一一对应（`chain_idx` 依赖各自词库内的后继词，词库不同则数值不同）。

## 关键约定

- 难度评级：原词库词保留其难度；ECDICT 新增词由考试标签/柯林斯星级/词频推导（0-10）。
- 常见度 `f`：由 ECDICT 词频排序归一化（越高越常见，供 AI 词频优先）。
- 非词库词在人类玩家出词时先确认（"不在词库、不计入难度统计"），确认后才接受；AI 出词必须来自词库。
- 数据与网页分离：词库与规则在服务端，网页只通过 `/api/start`、`/api/action` 等接口交互。
- 知识点：每个词最多展示 1 条（≤80 字直接显示；过长则存完整版并显示"打开提示"按钮；无配套则不显示）。

## AI 选词评分（可接指数 + 随机）

`score = 硬门禁(H) × (w1·防疲劳 + w2·难度贴合 + w3·词频 + w4·可接指数) × 随机因子S5`

- **硬门禁 H ∈ {0,1}**：规则合规 + **非死路**（有后继）。死路词绝不入选。
- **可接指数 = 词型分 × 可续性**：
  - 词型分：缩写(短且无元音/`abbr.`)≈0.05、地名/人名/姓≈0.10、普通词≈0.90。
  - 可续性：该词**后继的质量加权和**（后继也按"词型分×词频"加权），而非个数——所以"后面大多能接缩写"的词可续性被真实拉低。
- **权重(默认)**：防疲劳0.30 / 难度贴合0.23 / 词频0.23 / 可接指数0.24；**S5∈[0.93,1.07]** 为乘法随机因子，只在合格候选间扰动。
- **结尾多样化**：AI 统计最近 10 个"喂给玩家的结尾"，重复的结尾受 0.55~1 的软性惩罚，避免"st/re/al/le"等好接结尾扎堆。
- **教学导向（登录账户）**：候选若"含知识点且该账户未见过"，额外 ×(1+0.18)，帮你在玩中学新词。
- **防疲劳改为软性**：按"全时段使用次数"给 0~1 惩罚（用越多分越低），不再绝对禁选。
- **常态化/持久化**：防疲劳的"全时段已用词"存到 `data/usage.json`，**跨网页/跨会话继承**——重开页面、换新一局，AI 都会记得历史上用过的词并尽量避免重复。重置：`POST /api/reset-usage` 或删除 `data/usage.json`。
- **难度/常见度 = 多源综合**（避免单源偏差）：每词的 `d`/`f` 由 ECDICT(COCA/BNC 语料排序 + 考试标签 + 柯林斯星级 + 牛津) + 原词库(自带难度/词频) + Kyle(考试级别/词序) **共同推导**——常见度取语料/词库频率均值；难度以考试标签/级别为主，柯林斯压难度、罕见度微调、词长兜底。
- **AI 认输需确认**：AI 无词可接认输时**暂停**并弹出"AI 认输了，你 +1 分，确认继续？"，玩家点"确认继续"（`/api/action kind=continue-round`）才进入下一轮。

## 死路 / 最死组合预警

- 每个词预计算 `可续性(chain)` 与 `可接指数`；服务端快照附带 `dead`(是否死路)、`chain_idx`。
- 前端面板对**死路词**（无后继）显示 ⚠️"这个词结尾几乎接不下去"；对**低可续性**(chain_idx<0.08)显示 ⚠️"这个词结尾不好接，小心卡壳"。
- 最死组合（用新词典筛查）：`-ght(ht)`（light/right/thought 家族，115 词 100% 死路）、复数+s(`ds/gs/ks/ws`)、`tz/zz/rf` 等。已过滤掉只有 1-3 词的缩写/怪词噪音。
